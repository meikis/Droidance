# Programmable environment

## description
Task-owned JavaScript execution in an isolated Android worker. Use environment for actual APIs and limits, workspace for durable files, run for a script, poll to supply input or resume after a visual decision, and cancel to stop an exact handle. Deterministic computation and host requests continue within the task-owned invocation until exit, a real decision boundary, cancellation or timeout; no periodic model poll is needed to service them. The worker has no direct Java, network, OS process, credential or raw filesystem APIs. android.call("shell", ...) requests device-wide shell through the same bound host executor; worker isolation does not sandbox that device capability. Script exit is not task completion. Keep visual decisions grounded in images you have actually inspected; JavaScript receives observation references and text, not visual understanding.
For nonvisual bulk summaries, prefer one program for scoped paginated reads and deterministic aggregation; print compact results and source/coverage facts instead of passing every raw page through another model round.
Skill runs additionally expose typed parameters and skill.read(path), which reads only the exact frozen Skill package. A Skill revision is never reloaded during execution.
Available globals: android.call(toolName, argumentsObject), workspace.read(path), workspace.write(path, text), workspace.list(), workspace.artifact(ref, offset), print(value), readLine(). Android tools are not global JavaScript functions: use android.call, never android_read(...). Child results expose outputText (retained tool text, not an assumed parsed object), executionStatus and diagnosticCode. Use print for output; console.log is unavailable. Run is a top-level script, not a function body: do not use top-level return. Consult environment before using any other API. On script failure, correct the reported code/API error before retrying; do not repeat the same invalid program.

## environment
Availability: Android API 29 or later; environment reports unavailable on API 28.
Runtime: Rhino 1.8.0, interpreted JavaScript (ES6 subset), isolated Android UID. No Python, Node, Java/Packages, subprocess, raw filesystem, or direct network APIs. Shell access is mediated by android.call, never a worker subprocess. Each run starts fresh variables; workspace files persist across this task's rounds and compaction. Committed files remain readable after process restart; worker variables and execution handles do not resume.
APIs:
- workspace.write(relativePath, text), workspace.read(relativePath), workspace.list(), workspace.artifact(ref, offset). artifact reads retained textual tool/source data in pages; images require the Agent to use workspace(op="artifact") and inspect the actual image. Files are UTF-8 and bounded; absolute and parent paths are rejected.
- print(value) appends output. readLine() consumes stdin lines supplied to run/poll; when none are available the run waits until a later poll supplies input.
- android.call(tool, arguments) synchronously uses android_read, android_act, screen_act and shell through the task's bound executor. Returned value has executionStatus, outputText, diagnosticCode, observationId and evidenceStatus. A failed or unknown device call aborts the run; inspect before choosing a new program. No terminal tools, direct OS APIs, Skills, permission bypass or hidden model calls. Shell results expose structured data.stdout, data.stderr, data.exit_code and data.execution_status; retain data truncation flags. A shell script exit does not verify earlier statements. All children inherit the original invocation deadline, device access and mutation restrictions.
For multiple actions grounded in the current image, call android.call("screen_act", {actions: [...]}) once; its ordered actions run within the same invocation and return one final observation. Do not issue separate screen_act host calls for that group, which would introduce observation boundaries. After the group or an individual Android action, inspect its returned state. A script cannot infer newly visible coordinates from old screenshots. End the run when a new visual decision is required and let the same Agent inspect the returned frame. For nonvisual operations, use ordinary loops, conditions and parsing when the next step is justified by returned data.
For nonvisual record summaries, select only the required Provider columns and rows. Use one task-owned program for data-dependent pagination and deterministic counts, grouping, totals, sorting and timestamp conversion when these depend only on returned data. Parse the actual outputText structure; preserve source references, row counts, scope, has_more, offsets and truncation. Do not assume an undocumented response shape or infer completeness from an empty/error page. Stop on permission denial, unknown execution or an inconsistent page; report partial coverage rather than silently dropping it. Print the compact requested aggregate, coverage and only the supporting rows needed for the answer, rather than forwarding every raw page to another model round. Retain required originals in the existing workspace/EventStore. Use a retained receipt for a missing calculation instead of querying unchanged data again. Do not invent meanings for undocumented enum values.

Visual collection remains image-grounded: a program cannot extract facts from observation references. Inspect each delivered capture group, preserve useful deltas, and continue the unexecuted suffix only when new evidence is required. Do not recapture an already readable saved page merely because a stability or byte-budget diagnostic interrupted later actions.

Tool operations: environment; run(code or path,stdin); poll(handle,offset,stdin,resume); cancel(handle). offset is a UTF-16 character offset in stdout; next_offset resumes exactly. waiting_for_input requires stdin. waiting_for_observation means the next Android call has NOT executed: inspect the newly delivered screen before choosing to poll or cancel/replan the remaining script. Polling across this boundary requires both a fresh bound model observation and `resume={boundary_id,pending_action_hash,observation_ref,decision:"continue"|"replan"}` copied from the returned boundary and the current inspected frame. Continue approves the exact pending request; new screenshots alone do not approve old targets. Replan closes the old worker, keeps completed receipts, and discards its unexecuted suffix. Never replay completed or uncertain effects. `stdin` cannot rewrite an already queued Android call: only a script intentionally waiting at `readLine()` can consume newly chosen arguments. Old prequeued input is cleared at visual boundaries; supply new input with the acknowledged poll. For example, a script may run a grounded batch, then `var next = JSON.parse(readLine()); android.call("screen_act", next);` so the same Agent inspects the returned frame and supplies the next grounded request. The boundary reports the actual pending request, completed calls and unknown effects; dynamic future script calls are not an invented list of executed actions. Use screen_act(actions=[...]) for actions already grounded in one frame; stop or use readLine() when fresh visual judgment must determine new arguments. Old handles are task-scoped and are never restarted. Waiting runs emit snapshot records; every settled worker emits one idempotent terminal record, including cancellation and failures. Read receipts_ref for the complete child-call receipt list; failed_child or unsettled_child identifies the failed or unknown operation. A terminal worker does not settle unknown Skill items or authorize replay. All code/output and original child receipts have immutable artifact/event references; script output remains model-authored computation, not independent source verification.

Use session_read(mode="programs", after=sequence) to discover original program events after compaction. Use session_read(mode="artifact", ref=content_ref, offset=next_offset) to read complete retained text or attach an original historical image. Historical images do not replace the current observation lease. Output beyond the configured total cap stops the run explicitly; output already admitted stays retrievable. Files and immutable evidence follow existing task-history retention; closing a worker does not delete task files.

Pure computation and App-UID ContentProvider calls require no display or shell. Set device_access=true only when the planned script needs a backend. If a local run returns waiting_for_device, the pending child has not executed; use poll(handle, device_access=true) in Android activation to bind the backend or cancel. A local-knowledge session cannot promote itself to device access. Never replay a run handle to resume it.

Use device_access=true on each run or poll that will service device requests, including an already bound handle; an old binding does not grant access during a local invocation or restricted review. Use android.call("shell", {command: "getprop ro.product.model", expect_screen_change: false}) for a nonvisual query. Consume its actual data before computing the next request. Device mutations still require authorization. A shell call expecting screen change, or with unknown effects, invalidates the old visual state and introduces the same Agent observation boundary. Avoid long visual scripts: use a grounded screen batch, inspect its final frame, then choose remaining work. Command logs describe actual host invocations; print output is model-authored computation.
